# Q12 公開共通CSS/JSの転送量

## 原因・範囲

隔離Flask配信でstyle.cssが834,485B、base.jsが103,926Bのまま転送され、
低速回線では初回表示の大半を占めた。CSS規則やJS処理を削る変更ではない。
計測対象の公開2ファイルだけ、gzip対応要求へ可逆圧縮して配信する。
その他の静的ファイル、アップロード、マニュアル、動的HTMLは対象外。
実配信エッジの圧縮状態は確認しておらず、ローカルの効果を本番の保証にはしない。

## HTTP・安全性

- Accept-Encodingの品質値を確認し、非対応/identity優先/効果なし/読込み失敗は従来配信。
- 圧縮版と非圧縮版のETagを分離し、Vary: Accept-Encodingと304再検証を維持。
- HEAD/Content-Length/MIME/Last-Modifiedを設定。Range要求は従来のidentity経路。
- 公開パス2件を固定し、symlinkで非公開領域へ向けられたファイルは404にする。
- 元のstatic処理を包み、既存before/after requestの認可/セキュリティヘッダーを維持。
  ルート・DB・フック・フィルターの契約は変更しない。
- ファイル版を毎回確認し、公開データ専用のapp-local LRU（8MiB/16件）で圧縮結果を再利用。
  非公開表示画像のキャッシュとは分離する。CSS/JSの元ファイルは不変。

## 確認

gzip展開後の完全一致、MIME、Content-Length、品質値、表現別ETag/304、HEAD/Range、
ファイル更新の鮮度、圧縮再利用、非公開/対象外/欠損、失敗・効果なしのfallback、symlink拒否をテスト。
公開配信でDBへ接続しないことも検証する。
Windowsのsymlink権限がない場合だけ当該試験をskipし、Linux CIで実施する。
既存アプリ契約テストも維持。

実ファイルの圧縮実体はCSS118,923B/JS21,144B。展開後は834,485B/103,926Bで元と一致。
同じ架空200台/合成プロフィールのPC/mobileで各3回、通常/150ms・下り200,000B/s・CPU4倍を比較。
初回と再表示、HTTP TTFB/app/SQL、転送量/展開後量、load/FCP/CLSを区別する。
確定中央値/範囲とCIはPR本文および日本語完了報告を参照。

実S3/本番インフラ/配備設定へ接続・変更しない。
