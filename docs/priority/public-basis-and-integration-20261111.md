# 確認・対応優先度の共通接続と公開資料の対応

## 目的と境界

仕様 U39 の優先度は、確認・対応の順番です。事故確率、故障率、残寿命、安全証明、運行可否ではありません。有効な区分は高・中・低だけです。情報不足は具体的な確認事項として区分と分けます。国・メーカーの公開資料は事実と適用条件の根拠であり、100点方式の点数を規定したものではありません。

承認済みの試行規則は I 最大40、T最大35、S最大25、基本点と下限の最大値、低0–24、中25–59、高60–100です。25/60、30日、90%はシステム独自の試行値です。本格運用前の整備専門家確認は、代表事例・見逃し・過剰判定・適用範囲をまとめて行います。開発や隔離試験を止める条件ではありません。

## 一次資料を2026-11-11に再照合

- 国交省「点検・整備の推進」 https://www.mlit.go.jp/jidosha/anzen/03safety/inspection.html
  事業用車の日常点検は運行前に実施し、制動、タイヤ・ホイール取付状態等を確認します。運行可否を決定する主体は整備管理者です。今回の限定された標準点検項目を安全機能に対応付ける根拠です。×の自由文解釈や、全車種一律の期限・点数の根拠にはしません。
- 国交省「車輪脱落事故」 https://www.mlit.go.jp/jidosha/jidosha/tenkenseibi/tenken/t2/t2-1/
  大型バス・トラックの車輪取付作業・増し締め・日常点検を説明しています。50–100kmの目安は対象作業と条件のある増し締めの説明であり、全てのタイヤ交換・部品交換の共通期限ではありません。元の交換・走行・作業記録がない提案へ機械的に適用しません。
- 日野「大型車の車輪脱落事故防止のために」 https://www.hino.co.jp/ts/wheel_fall_off/
  ホイールボルト/ナットの欠落、突出状態、車輪材質・使用ボルト等の具体条件を説明しています。実車の適用装備と観測事実が一致したときだけメーカー条件を評価できます。単なる「タイヤ」や「ブレーキ」の記載、AIの重大判定から即時対応条件を認定しません。

公開ページの一般注意だけで新しい停止判断を作りません。既存の権限者判断は、元記録と日時・現在の有効性を独立して保全します。

## 通常経路と互換

- 元の保存提案から proposal_id / proposal_revision を確定してから、別の priority_assessment を応答用コピーへ付加します。保存JSON、回答キー、出典、入力snapshotを書き換えません。
- 算定可能な厳密対応だけに新点数を表示します。未接続の旧提案は保存済みの高・中・低を維持し、点数は付けず、保存版であることと不足を説明します。これらは算定データの状態であり、第4の優先度ではありません。欠損や不正値を低へ置き換えません。
- risk_status は機能影響の説明根拠の状態として残します。旧C×L表のresponse_priorityを確認・対応優先度として再利用しません。
- 新しい通知発行、既読変更、AI再生成、DB変更、運行判断の変更はこの読取接続の副作用にしません。
- #362の既存shadowコアの本番防止は維持します。今回の統合は別の版付き契約で、純粋算定を検証済み事実に限って利用します。既存draft branchも変更しません。

## 本格運用前にまとめて確認する論点

1. 標準点検項目の具体的な不良回答からI40を与える限定範囲と、チェック項目を改変した場合の扱い。
2. 中50点と、未接続の高60点下限等の順番が実例で過剰/過少にならないか。中は運行可の意味ではありません。
3. 運行不可・確認指示の現在性、撤回・再点検・別事象の扱い。指示の解除は人が行います。
4. 時期の採点へ進む際の、メーカー基準の適用範囲、起算記録、AND/OR、暦月90%の定義。今回未接続のケースを無理に採点しません。
5. 旧提案の根拠付け拡張、新規生成・定期点検・通知/集計との共通契約。3画面の接続だけで仕様全体完了とはしません。

この文書は開発対象と照合根拠です。マージ・本番反映・整備作業・運行判断を承認するものではありません。

## 今回の通常入力の限界

新規の正常分析生成からは、24文字以内の標準ブレーキ項目（daily_02、daily_03）の原文と出典を保持するよう生成契約を補います。原文が長い車輪項目 daily_18 は今回の通常正規化へ接続していません。現行24文字target制限に加え、明示した項目参照の契約が必要です。短縮名を勝手に同一視しません。長い項目、複数指摘、整備/メーカー周期、定期点検、悪化/再発、通知と集計は、明示項目参照と元事象の版を拡張する後続範囲です。

今後の正常生成でinspection出典にserver-owned priority_provenanceを付け、元の対象事象・当初回答・項目定義を厳密照合し、現在の対応状態と停止判断の登録履歴は別に確認します。元事象の版証明がない旧提案や、別の指摘へ変わった提案を推測で付け替える移行処理はありません。同じ対象事象に関係しない表示属性や別の点検の追加だけでは、照合済みの点数を消しません。

## 独立レビュー後の第一段階の限定

運行不可の記録、未解消の修理・再確認が関わる提案は、元データだけでは解除範囲や旧判断履歴を確定できないため、今回は新方式の点数を付けません。保存された高・中・低を無点数で保持し、判断と元記録の確認事項を別に示します。古さや無関係な点検追加を理由に、新しい高60から中50への降格を作りません。通常経路で新算定するのは、元事象が厳密に対応する、停止判断・修理再確認のない標準ブレーキ指摘の中50点です。中下限25・高下限60、時期等の純粋計算試験の成功を、通常入力でそれら全てを接続済みという意味には使いません。

同じ提案IDが複数現れる既存データでも、IDと回答キーを変えず、元配列の位置を使う完全な並び順をサーバーから渡します。
