# 運転日報詳細の表示（2026年10月27日）

仕様書v0.21のF093・K22・K27・K29・K31・K32に対応する表示の補完。運転実績一覧のモック反映とは独立して、日報詳細を運行概要、登録済みの確認内容、読取項目、管理者の記録操作の順に整理する。

- 概要では乗務員・日報の事業所・距離・開始と終了の時刻・帳票名を表示する。全帳票情報は折りたたみ内に保持し、現在所属を過去所属として補わない。
- 実測値・評価、発生事象、乗務・作業、独自項目は取得済みのものだけを表示する。原文値、点数の0、備考を保持し、未取得を0にしない。原文にある開始・発生時刻、終了時刻、場所をそのまま表示し、日付・秒・座標・走行軌跡・原因を作らない。
- カードの「数値・条件・対象を確認」で数値・単位・分子・分母・定義・閾値・道路区分・乗務員コード・車両番号・話者を確認できる。見出しと値はPC・スマートフォンの同じHTMLを使用する。
- 管理者には、明細の整数ページが日報の原本ページ一覧にも含まれる場合だけ、既存の権限付きPDFルートへページ指定リンクを表示する。一般ユーザーには原本ページ番号を表示し、PDFへのリンクは表示しない。原本の閲覧権限は変更しない。
- 確認・指導の記録は既存のフォーム・CSRF・版・会社権限・監査処理を使用する。登録された行動・本人の説明・確認内容・次回日・比較根拠は本人も読み取れる。一般ユーザーに編集や本人閲覧設定・取込取消を公開しない。
- 「確認・指導を記録」「帳票情報を確認」への移動では対象の折りたたみを開く。スマートフォンでも見える「運転実績へ戻る」から、検証済みの元URLと条件へ戻る。

検証は一時SQLiteでの `test_driving_report_detail_ui.py`、既存の日報・共通基盤・レスポンシブ試験、JavaScript試験と構文確認を使う。ブラウザでは原文の時刻・場所、該当ページ、フォームの保存・戻り、本人との分離、320/390/430/768pxとPCの横はみ出しを確認する。OCR自体の精度、実資料の意味、業務基準の受入、有料AI、本番データを変更する作業は今回の表示検証に含めない。
