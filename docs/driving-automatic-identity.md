# 本人の運転実績の自動照合

2026-10-28の利用者指示「本人の情報を自動で自分の実績へ表示する」に対応する。v0.22の22～23ページにある「通常作業を増やさない」「確認済み対応を次回取込へ再利用」を実装し、初回も既存台帳の社員IDとアカウントから一意に特定できる場合は設定操作を追加しない。氏名だけの一致や使用車両の閲覧登録は根拠にしない。

- 初回：同じ会社の乗務員台帳の社員IDとユーザーのログインIDが日報コードに一致し、3者の氏名も一致する場合。台帳・アカウントともコードごとに一意であること。空白と全半角のみ正規化する。営業所・車両の所属は本人照合の条件にしない。
- 後続：有効な明示確認がある同一会社・出力システム・コード・氏名の対応を、確認根拠の日報日以降へ再利用する。異なるアカウントへの対応が競合するときは保留する。過去にさかのぼる確認やコードが異なる資料の対応は推測しない。
- 日報単位の明示設定を優先する。古い確認、明示的な公開解除、別会社、不一致、社員ID重複、出力システム・氏名・コードの欠損は自動公開しない。
- 画面、詳細、集計、CSV/PDF、AI入力は同じ実効本人対応を使う。管理者本人にも適用する。GETではDB更新・有料AI実行を追加しない。手動設定は例外の訂正用として残す。

検証は既存の本人閲覧・管理者本人・所属・集計・AI・出力の回帰と、`tests/test_driving_automatic_identity.py`。通常取込に設定作業を追加せず、別人の数値を含めないことを確認する。日報関連170件と、実ブラウザーで設定操作なしの本人5件表示・管理表示・詳細の自動照合表示・390pxの横はみ出しを確認。DB参照回数の既存検証も維持する。本番での受入完了ではない。

作成済みテストPDFの `TEST-SHIOKAWA-01` はログインID `78678` と異なる架空コードであり、氏名だけで自動対応させない。検証用資料のコードは既存社員IDへ合わせるか、資料確認時に正しいコードへ訂正する。コードが違う実資料には、確認済み対応の再利用を使う。
