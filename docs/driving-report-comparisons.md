# 運転傾向の比較

仕様書 v0.21 の F093 に基づく運転実績画面。集計・比較はローカルの確認済み記録を利用し、AIの振り返りは明示的な作成操作で非同期に実行する。既存資料のOCR再読込は不要。

- 初期期間は日本時間の当月初から当日。直近30日、前月、任意期間、全期間へ変更できる。比較先は直前の同じ日数。出力にも画面と同じ期間・範囲・選択乗務員を適用する。全期間を出す場合は明示的に全期間を選ぶ。
- 乗務員・営業所・車両を絞り、指標を切り替えて横に比較する。原本だけにある値も一覧と詳細に残す。
- 同じ提供元・設定版・定義・閾値・単位・道路区分・粒度の値を比較する。回数と対応する距離から回／100km、明示された分子・分母から率を算出する。期間燃費は距離合計／対応する消費燃料合計で計算する。日別燃費の単純平均や、原本の点数の平均・順位は作らない。
- 距離0・欠損、CSV照合待ち、異なる定義を混ぜない。原本値0と欠損を区別する。グラフは実測の2点以上だけを描き、欠損した記録を0として接続しない。
- 同じ運行の資料やCSVは一度だけ扱う。日別計と運行明細、月次計と日報は重ねない。重複資料の値が異なる場合は照合へ案内する。
- 乗務員は会社・提供元・コードで区別する。同姓同名でコードがない資料、同一コードで氏名が食い違う資料は原本ごとに表示する。人によるコード変更・再利用の名寄せ画面は未追加。
- 乗務員を選ぶと日別推移、日報へのリンク、使用車両の直近の完了整備を表示する。整備は対象期間末までの記録で、会社と車両を照合する。故障原因、クラッチの摩耗量や寿命は推定しない。
- 詳細の確認・指導に「改善する行動」と「乗務員の説明」を追加。既存の履歴、版照合、CSRF、担当と次回確認を利用する。保存や戻るでも期間・乗務員選択へ戻れる。
- 日報CSV、比較CSV、PDFに同じ期間・フィルター・指標条件を適用する。比較CSVには分子・分母・日報ID・原本値の対象日を出力する。CSVの数式対策を維持する。

- 「比較の前に確認する日報」で距離の欠損・0km、CSV照合待ち、コードの不足・氏名の食い違い、比較条件の未記載を理由付きで案内する。確認後は同じ期間・絞り込みへ戻る。取消済み資料や重複の写しは案内を水増ししない。原本の値や条件を自動補完しない。

## 検証

`python -m unittest discover -s tests -p test_driving_report_insights.py`

`node --test tests/driving_report_insights_js.cjs`

実資料に記載された検知閾値と設定版、最低記録量、コードの再利用、燃料の対象期間は、仕様書 U40 に従って業務受入で確認する。未知の条件は補完しない。CSVで供給されない時刻や映像を作り出さない。

## 外部利用に向けた画面と閲覧範囲

- 管理者は所属営業所を初期表示し、同一会社の他営業所・会社全体を選べる。所属未設定では範囲を選ぶ。営業所ではAI要約・主な指標・乗務員一覧、会社全体ではAI要約・主な指標・営業所一覧を表示し、営業所から個人詳細へ進める。全乗務員への横断検索も用意する。乗務員検索・確認状態は一覧側に置く。
- 一覧は氏名・主な傾向・記録量・対応状況を中心にする。スマホはカード表示。乗務員マスタにある日報なしの人も表示し、本人対応未確認と記録なしを区別する。OCR氏名やコードだけで本人と統合しない。現在所属を過去の運行所属へ遡及しない。
- 比較先は「直前の同じ日数」か「開始日の前月全体」。対象日と比較日を画面・出力へ保持する。回/hなど明示された対応時間のある率も分子合計／分母合計で計算する。
- 記録上の0、距離未取得、その指標の記録なし、前期間の比較記録なしを区別する。順位や安全性の自動判定は行わない。英日併記の既知の項目名とHH:MMの時間は表示だけを整え、原文は詳細に残す。
- 管理者（admin/itc）はログイン中の会社全員分を閲覧できる。一般ユーザー（user）は、管理者が本人を明示的に確認して設定した日報だけを閲覧する。一覧・詳細・集計・比較CSV・日報CSV・PDFのサーバー側で制限し、クエリやURLの変更では範囲を広げられない。
- `DrivingReportReader`を追加。会社、日報、ユーザーの不変ID、確認時の乗務員情報ハッシュ、確認者・日時を記録する。氏名、乗務員コード、取込者、営業所が一致しても自動公開しない。既存ユーザー名が別アカウントに再利用されても閲覧権限を引き継がない。
- 管理者は日報詳細で1件ずつ、乗務員詳細で現在の期間・絞り込み内の日報をまとめて設定・解除できる。更新版を照合し、操作を日報監査履歴へ残す。氏名・コード・日付・車両・提供元の訂正で確認時情報が変わると再確認まで一般ユーザーには表示しない。
- 一般ユーザーは閲覧のみ。管理者の確認・指導、本人説明、次回確認日を読める。編集、CSV照合、取込取消、本人閲覧設定、車両全体の整備履歴、他人の情報を含み得る原本ファイル、訂正前の監査スナップショットは公開しない。原本が複数人・複数日報を含み得るため、本人日報に紐づいたという理由だけでは原本全体を公開しない。
- 今後取り込む日報は自動で本人公開しない。人が確認した対象範囲に限る。自動公開の運用を追加する場合は、提供元コードと社員IDの正式な対応表・有効期間・再利用ルールを別途確定する。

### 配備

Gunicornのworker初期化で追加テーブルだけを作成する。既存列の変更やGETでのDDLは行わない。ローカルでは `py -m flask --app app init-driving-access` を実行する。本人閲覧設定と振り返り結果の保存先を冪等に作成する。未準備時は権限を広げず、設定・AI作成は503で停止する。

### スマートフォン表示

650px以下では乗務員比較・日報一覧・日別記録・整備履歴を、同じデータを使ったカード表示に切り替える。指標名と単位を各値の近くに表示し、横スクロールなしで詳細と原本の操作へ進める。表の行・列の意味は明示的なARIA roleと列見出しに残す。PCでは従来の比較表を維持する。

対象乗務員の識別不足を「0人」と表示せず、期間内の対象日報数を表示する。本人確認・閲覧権限・集計値は変更しない。入力欄の共通余白、非表示パンくずの余白をこの画面内で解消し、スマートフォンの入力文字は16px、主な操作は40px以上とする。

## AIの振り返り

- `DrivingReportReflection`へ生成状態と結果を保存する。会社、アカウントの不変ID・ロール、会社全体／営業所／個人、期間、絞り込み、日報の版、閲覧対応、参照整備履歴を入力ハッシュへ含める。毎回の取得時に現在の権限と入力を再計算し、訂正・取消・対応解除後の旧結果を返さない。
- 通常GETで有料APIを呼ばない。作成POSTはCSRFと入力ハッシュを確認し、DBの一意制約と状態で二重生成を抑え、スレッドで実行する。1アカウントにつき毎分6回に制限する。再起動等で3分以上残った処理は再試行可能とする。
- 数値、表示文、出典日報、比較条件はプログラムが作る。AIは候補の優先順位と許可済みの次の行動を最大3件選ぶ。存在しない根拠、許可されない行動、架空の数値は回答へ採用しない。失敗は失敗として表示し、再試行できる。
- `OPENAI_API_KEY`と既存の`OPENAI_MODEL`を利用する。専用モデルは`DRIVING_INSIGHTS_MODEL`で変更できる。APIの保存は無効。今回の試験は外部応答を模擬し、有料APIは実行していない。
- 候補は全体集計を先頭に最大200件。超える場合は部分要約と表示し、個人詳細で絞れる。全員を網羅した査定や安全判定とはしない。
- 初期実装は記録の要約・確認候補・定型の行動提案。メーカー交換基準を検索するRAG、故障確率・部品寿命・節約額の推定、自動の人事評価は実装しない。整備については管理者が閲覧できる選択乗務員の使用車両履歴へ接続する。

検証：`python -m unittest discover -s tests -p test_driving_workspace.py`。実資料・最低記録量・運行条件とAI提案の業務受入はU40・K21～K40で継続する。
