# 整備後の請求書と点検計画の実施概要

仕様書本体 v0.25（2026-10-28）で採用した、整備後の請求書を実施済みの履歴として扱う動作と、点検計画から原本を開く動作を実装する。

請求書を確認登録すると、整備実績を完了状態で保存する。既存の請求書由来の記録はデータを一括書換えせず「実施済み」と表示する。読取データの訂正は保存前の作業状態を維持し、不具合対応・再確認・運行判断を進めない。通常の手入力の作業進行は維持する。

点検計画は既存の整備実績と登録済み原本の関連を参照して、実施日と作業内容の一言概要を表示する。月間一覧・年間表・カレンダーのリンクから既存の車両書類原本URLを開く。完成済みの突発修理は既存行を利用し、概要を重複表示しない。確定済みの後着請求書にも対応する。請求書や入庫日から実施日を推測せず、完了日のない記録は実施日不明として月間一覧・年間の車両欄に表示する。

点検計画の作成・完了・次回予定計算・予約変更・通知は、この概要表示では実行しない。通常整備を定期点検の実施に読み替えない。原本の複製やDBスキーマ変更は行わない。概要APIは原本バイト列を取得せず、リンク先が既存の会社・車両・登録済み原本の認可を検証する。

## 検証

- 専用の実Flask・一時SQLite試験11件：実取込、実施済み表示、原本一致、旧記録の訂正と状態維持、完了操作の拒否、実施日不明、再読込、既存予定の保持、後着請求書、複数原本、会社・車両・原本境界。
- 関連試験：点検計画53件、業務回帰52件、資料接続6件、資料日付8件。専用を含め130件成功。
- 実テンプレートと実API応答を用いたDOM確認6件：月間リンク、年間の実施月、カレンダーの実施日、定期点検種別との分離、実施済みフィルターで請求書だけある車両の表示、複数原本の選択。
- JS構文とgit差分の空白検査を実施。

ブラウザの実画面、外部AIの実通信、本番への配備は別途確認する。点検計画のExcel出力への一般整備概要追加は今回の対象外。元の請求書原本を訂正する機能は追加していない。
