# M06 車検と12か月点検の独立管理

基準main: `0919278742e4f21f08c405b3946d2f8fec410bc4`（ユーザーが#349をマージ）。
11:19および11:50の承認済み仕様を実装する後続差分。#349の終了済み通知再発行防止を維持する。

## 保存・読取

- 既存String(30)列を再利用。新規12か月点検は`periodic_12month`、車検は`vehicle_inspection`。公開画面/APIの12か月点検選択値は`12month`。
- 既存の種別を更新・削除しない。旧`12month`行は、会社・車両・原本・明細index・登録結果・確認値が整合する12か月原本を読取で確認する。確認登録を信頼する従来契約を保持し、新マーカー不在だけで失効させない。
- 根拠が不足・矛盾する旧行は「車検／12か月点検・区分未確認」と表示。車検証満了日や新規登録から旧種別を推測しない。
- 同車両・同日の両実績を保存可能。確定した同種実績との重複は拒否。旧不明行と重なる新規分は、その新規種別・実施の根拠確認を要求する。旧行の完了・分類確定・紐付けは行わない。
- 旧不明予定と重なる新規予定は根拠を要求し、既存PlanEventのJSONに根拠・重複候補IDを保存する。
- 旧画面からの年間種別書込みは再読込を要求。新フォームの契約値は保存方式を識別するためのもので、旧確認済み実績の有効性判定には使わない。

## 期限・通知

- 車検証満了日候補は車検のみ。車検の次回周期を推測しない。12か月実績から車検証満了日を変更しない。
- 区分未確認旧行に依存する通知のみ自動終了・追加再通知を保留。未終了の表示・既読・receipt、終了済みの状態を保持し、未配信の抑制を解除しない。
- 確定した両種別・3か月・突発修理の通常通知を維持。会社・車両・通知先認可の失効処理は維持する。
- 車検と12か月点検が同じ月に必要なら独立した通知になり得る。片方の実施を他方の完了根拠としない。

## 原本・案件

ExecutionEvidence.document_idは既存ImportDraft.idを参照し続ける。MaintenanceDocument.idやchecklist用Linkを転用しない。複数実績から同じ原本を参照でき、原本の会社・車両・明細index・登録結果・ハッシュを検証する。

確認済みMaintenanceDocumentから一意の整備案件を辿れる場合、または旧請求書の既存source JSONと登録結果が一致する場合だけ案件リンクを表示する。複数案件の原本は推測で一件を選ばない。実績、PeriodicRecord、原本、案件を複製しない。原本だけを根拠に別種別の実施済みを自動登録しない。
