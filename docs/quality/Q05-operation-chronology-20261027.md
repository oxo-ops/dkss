# Q05 運行実績CSVの日時前後関係

基準コード：main de787a1（2026-10-27取得）。社内テスト用の架空データで再現・検証した。登録済みデータの補充や実車照合は対象外。

## 修正理由

従来のCSV行パーサーは日時ごとの形式だけを検証し、入庫日時が出庫日時より前でも受け付けていた。確定ルートも同じパーサーを使うため、プレビューを経由しない確定POSTで逆転した実績が登録された。正常行と逆転行を同時選択した場合も拒否されなかった。

追加試験で逆転3ケース、確定ルート2ケースの計5失敗を再現した。これは仮データで再現したシステムの入力検証不備であり、既存データの逆転を確認した意味ではない。利用者提出の日付診断では既存運行2,571件の逆転は0件だった。

## 変更

- 出庫・入庫日時が両方ある場合、正規化した完全な日時で比較し、入庫が前なら行番号付きの入力エラーにする。
- 日跨ぎ、年越し、うるう日、同時刻、片方または両方空欄は受け付ける。運行日の別の日への変更や欠損補完は行わない。
- 出力日付はisoformatで4桁年を含む固定形式に統一。strftimeのプラットフォーム別の年のゼロ埋めに依存しない。
- CSV取込・確定時の既存パーサー利用箇所で有効になる。既存レコード・DBスキーマは変更しない。

## 検証

追加8テストと既存CSV12テスト、業務回帰52テストの計72件が成功（32.898秒）。追加のルート試験は実Flaskと一時SQLiteを使用する。

- 秒単位・年越し・うるう日前後の逆転拒否
- 正常な日跨ぎ、同時刻、空欄の許可
- 不正暦日の拒否と4桁年の正規化
- 直接確定POSTの拒否と運行実績・車両対応表の非登録
- 選択した混在行を一部だけ登録しないこと
- 正常4行の確定と保存日時・空欄の維持
