# Q05 点検予定と通知の日付境界

基準コードはmain de787a1。社内テストの架空データと一時SQLiteで検証した。既存の登録データの補充や実車照合は行わない。本変更は追加テストと記録のみ。

## 日付の意味と精度

| 用途 | 受け付ける精度と扱い | 基準時刻 |
|---|---|---|
| 点検実施日 | 厳密なYYYY-MM-DD。年月のみ・不正日を拒否。未来の実施済み登録を拒否 | Asia/Tokyoの当日 |
| 点検予定月 | YYYY-MM。実施日や予約日を推測して作らない | 月単位 |
| 点検予約日 | 予定月内の厳密なYYYY-MM-DD。空欄は未予約 | Asia/Tokyoの当日で通知段階を判定 |
| 車検満了日由来の候補 | 正規の日付があるときだけ候補を表示。空欄・年月のみ・不正日から推定しない | 日付単位 |
| 点検通知 | 予約7日前・前日・当日・翌日、予定月前月・当月・翌月、期限当日と経過後を区別 | Asia/Tokyo |
| 点検計画の更新履歴 | UTCのオフセット付きISO日時 | UTC |

年月加算は対象月の末日に収める。例：2028-01-31の1か月後は2028-02-29、2028-02-29の12か月後は2029-02-28。予定月を計算する処理であり、不明な実施日を補完する意味ではない。

## 追加検証

`tests/test_q05_inspection_dates.py`の12件が成功（2.915秒）。アプリ処理の修正が必要な不具合はこの範囲では再現しなかった。

- 正規の日付だけを受け付ける。2000年・2028年のうるう日、1900年・不正日の拒否。
- 年月精度の維持、月末・年越し・世紀のうるう年規則を含む年月加算。
- 予定月・予約日・満了日の通知境界。満了当日を期限経過扱いにしない。
- UTCの14:59:59→15:00:00で日本時間の当日を切り替える。
- 実Flaskのプレビュー・確定経路で、未来の日が日本時間の午前0時から当日として登録できる。
- 不正日・別月の予約を拒否し、計画・イベントを作らない。
- 正常なうるう日の予約を保存し、年月だけの予定は予約日・実施記録を作らない。
- 不明な車検満了日から候補を作らず、登録処理も起こさない。
