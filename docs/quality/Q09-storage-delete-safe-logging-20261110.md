# Q09 添付削除失敗ログの機密情報抑制

## 対象と根拠

品質改善計画第26章「ログの保持と閲覧を管理する」とQ08・Q09の、秘密値や不要な個人情報をログへ出さない条件に対する限定修正です。既存の共通HTTP例外処理とは別に、添付削除で捕捉されたS3 ClientErrorとローカルOSErrorが、logger.exceptionから外部エラー本文・パス・ファイル名・tracebackを出力することを合成例外で再現しました。

基点は復旧版008ed6e41352a852828f10193972e6e415f9a20eです。変更前のstorage.pyはPR #362最終head efc365d416b78bd765183d579ad906b2944616d4と同一blob3897de4a7b2d8a12bcdd86ce02c1ec98c8887e95で、#361/#362の変更対象に含まれません。他の機能候補を再実装していません。

## 変更

delete_uploaded_fileの捕捉済みエラー2経路だけを、固定ERRORイベントへ変更しました。

- UPLOAD_DELETE_FAILED backend=s3 error_type=ClientError
- UPLOAD_DELETE_FAILED backend=local error_type=OSError

例外オブジェクト、可変引数、外部エラー本文、ファイル名、パス、tracebackをログへ渡しません。検知用の操作名・保存先区分・捕捉例外カテゴリを残します。S3の詳細コードやOSのerrnoはこのイベントでは記録しないため、詳細調査は別の承認済み手段が必要です。

削除先・回数・戻り値・捕捉対象・予期しない例外の伝播・既存無処理条件は変更しません。自動再試行や別保存先へのフォールバックを追加せず、エラー自体を成功扱いする変更でもありません。DB構造、認可、TLS、実ストレージ設定は不変更です。

## 検証

変更前の新規9試験は7成功・2失敗。S3/ローカル両方の実LogRecordと書式化ログに、合成canary、ファイル名、traceback、exc_infoが存在しました。

修正後は新規10試験と既存manual storage9試験、計19試験が成功、skipなし。新規試験は2経路の機密情報非出力、成功時の既存uploads/manuals先、未指定・不正会社・ローカル不存在の無処理、想定外エラーの同一例外伝播・再試行なしを確認します。正確な関数ASTだけでなく、importした実モジュールの関数でも2経路を確認しました。

全実行でstorage操作をmock化し、ネットワークconnectとSQLAlchemy Engine.connectを拒否しました。アプリ・DBを起動せず、実S3、実ファイル削除、本番には接続していません。独立レビューは製品差分と新規9試験を確認し、阻害指摘なし。追加の実モジュール試験を含む最終19試験は実装担当が確認しました。git diff --checkも成功しています。

## 残条件

この結果は対象2経路の限定受入です。全体回帰、対象候補のCI、実運用のログhandlerによる付加情報、ログ保管・権限・保持期間、その他のlogger.exception経路は別途確認が必要です。Q08/Q09全体完了、merge、本番反映を意味しません。

本候補は独立patchとして保持し、選定した最終統合版へ適用してから必要CIを確認します。稼働復旧2commitと#361/#362の採用済み差分を落とさず、ユーザー確認前のmerge・deploy・DB再構築は行いません。

## 専用CIの受入条件

独立した下書きPRを #361 の検証ブランチから分岐し、#361/#362 は変更しません。対象の専用workflowはPR headそのものをcheckoutし、SHA・tree・clean状態を表示してから19件を一回実行します。継承環境変数を空にし、ストレージ操作はmock、Pythonのネットワーク接続・待受・SQLite接続とSQLAlchemy Engine.connectを禁止します。合格には19件、skipなし、禁止IO試行ゼロ、DB接続試行ゼロが必要です。

既存自動回帰は統合候補の互換性を確認する別証跡です。独立修正のローカル合格試験をやり直すためではなく、採用候補の正確なソースと依存関係でCIを確認します。実環境のログ保持・閲覧権限・他の例外経路はこのCIの対象外です。
