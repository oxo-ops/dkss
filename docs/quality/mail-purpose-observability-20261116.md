# 認証配送の用途識別（非本番）

品質計画33.13の認証メールと任意通知の切り分けに対応する。
従来、MFAメールは通知送信関数を共用し、配送例外の purpose が常に
notification だった。MFAからの呼出しだけ固定値 mfa を指定し、通常通知の
デフォルトとメール変更の email_change は保持する。

ログのイベント名・段階・カテゴリは不変。purpose の許可集合に mfa を追加し、
未知値や str 派生型は unknown に落とす。本文、宛先、コード、例外全文は記録しない。
既存オフライン監視projectionの用途allowlistにも mfa を追加し、stage/error_typeを保持する。
新しいキーワード専用引数は既存の位置引数・opt-in挙動を変更しない。
送信回数、TLS、タイムアウト、#392のQUIT後受理保持も変えない。

既存監視は EMAIL_DELIVERY_FAILED を検出対象のまま維持する。用途を列挙して
絞り込む監視がある場合は mfa を追加してから採用する。これは分類改善であり、
認証コードの優先配送、到達、警告解消、正式監視の受入を意味しない。

合成試験: MFAの接続/TLS/認証/DATA/closeの5段階で mfa として安全に分類。
任意通知・メール変更の分類維持、不明メタデータのunknown化、no retry、
QUITエラー後受理、opt-inの回帰を検証。実送信・設定変更なし。
