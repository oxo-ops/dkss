## 確認した不具合

`dkss_app/vehicle_master.py` の `get_vehicle_date_error()` は `datetime.strptime(..., '%Y-%m-%d')` だけで検証していた。これは `2026-2-3` も受け付ける。新規・編集・Excel確定は入力をそのまま保存する。

一方、`dkss_app/dashboard_repository.py` の `inspection_vehicles()` は車検満了日をISO文字列でSQL比較し、`vehicle_inspection_plans.py` の `iso_date()` は厳密なISO表記のみ受け付ける。

再現：`2026-2-3` と `2026-02-03` を一時SQLiteへ格納し、`value <= '2026-11-01'` で抽出すると、後者だけが選ばれる。同じ暦日でも期限候補から落ちる。修正前のFlask新規・編集経路でも当該入力が保存され、期待する400でなく302になった。

## 修正内容

共通入力検証に半角数字の `YYYY-MM-DD` 全体一致を追加した。実在する日付の検証は従来のパーサーを使用する。

- 新規・編集・Excel確定で月日が1桁の入力を拒否する。
- 初年度登録日だけは従来どおり `YYYY-MM` を許可する。
- 空欄は不明のまま維持する。
- 不正な日付を推測して補完・変換しない。
- 既存レコード、DB型、索引、画面配置は変更しない。

Excelセルが日付型の場合は既存のプレビュー処理が `YYYY-MM-DD` に変換する。文字列の `2026-2-3` は確定時にエラーとなるため、正式な日付表記に訂正する。
