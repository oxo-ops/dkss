# Q05 ダッシュボードの日本時間境界

2026年10月27日。基準main：`f2549a9`（Q02のPR #212・先行Q05のPR #213取込後）。
車両日付の形式検証（先行Q05）とは別の差分。本番DB診断、Q02の権限検証、運転実績UIは変更しない。

## 問題と再現

`dkss_app/dashboard.py` の `dashboard()` は `datetime.now().date()` で今日を決めていた。サーバーのタイムゾーンがUTCなら、日本時間00:00〜08:59は前日になる。一方、点検計画・通知とダッシュボードの整備費推移は `Asia/Tokyo` を指定している。本番のサーバーTZ設定自体は未取得であり、本番で常に発生しているとは断定しない。

UTCサーバーを模擬したテストで、2026-10-26 15:00 UTC（日本時間10月27日00:00）にダッシュボードの集計終了日が10月26日となる不一致を再現。年末、うるう日開始・終了でも同じ不一致を確認した。日本時間23:59:59のケースは変更前も一致する。

## 修正

ダッシュボードの基準日を `datetime.now(ZoneInfo('Asia/Tokyo')).date()` に変更。この基準日は既存のScopeを通じて、車検期限残日数、90日以内の期限抽出、無事故日数、集計期間に共通で使われる。DBの保存時刻や保存済みレコードの書換えは行わない。
