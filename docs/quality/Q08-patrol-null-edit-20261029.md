# Q08 車両不具合の編集で保存済み状態を保持する

基点はmain `bdab9d85159d2091e1e3b09ed1f49e395eef3167`。
31列監査・前回20件・追加26件・#326の完了状態を保持し、それらの観測は再実行しない。

## 採用した動作

編集POSTにstatusがなければ、既存値を検証し直して補完せず、status列自体を更新しない。
旧NULLも正規の既存状態も保持する。statusが明示送信された場合は、従来どおり
未対応・対応中・修理完了だけを許し、空や未知値は400で拒否する。

旧NULLの編集画面では「状態未確認（変更する場合は選択）」を選択表示する。
このoptionはdisabledであり、Chromiumの通常のFormDataにはstatusが含まれない。
select本体は有効なので、利用者が正規状態を選べばその値だけを送信できる。
空のstatusを保持指示として許可する実装にはしていない。

新規登録は従来どおり、status省略時の未対応と、明示した不正値の拒否を維持する。
DB制約・移行・旧行の一括補正・履歴・一覧・通知・AIの状態処理は変更しない。

## 変更範囲と担当確認

製品変更は`dkss_app/patrols.py`の編集関数と、`templates/vehicle_patrol_form.html`のNULL用選択肢だけ。
公開PR #335・#334・#320・#318の全変更ファイルを確認し、対象2ファイルの重複はなかった。
Q03の承認/通知設定、運転分析の手動閲覧、Q02の通知配送と権限は変更しない。

## 修正前後の専用回帰

SQLite/PostgreSQL各8件、計16件。CSRFを有効にし、SQLite全接続のFKを有効にした一時DBと、
明示指定したlocalhostの専用PostgreSQL内のランダムschemaだけを使用する。

修正前は16件中、次の3件×2DB=6件で保護期待が失敗した。

- 実GETをChromiumで読み込み、本文だけを変更して実FormDataでPOSTするとNULLが未対応へ変わる。
- status省略POSTでNULLが未対応へ変わる。
- status省略POSTで既存の対応中が未対応へ戻る（修正後は正規3状態すべての保持を確認）。

修正後は16件すべて成功した。
正規状態の明示変更、不正値/空の拒否と部分保存なし、新規の未対応既定値、新規の不正値拒否、
別会社・一般利用者の編集拒否を含む。既存の認可条件・期待値は緩和していない。

Playwright 1.62.1を使ったChromium/Chromeのブラウザ検証は、実GETのHTML全体を読み込み、ネットワークを全面遮断して
native selectとFormDataの規則を検証する。ブラウザ内でstatusを除去する加工はせず、
フォームが生成したstatus省略をそのまま実Flask POSTへ渡す。
本文は既存リッチエディタのhidden contentの契約に沿って変更し、実エディタUI全体のE2Eとは区別する。
同じブラウザで正規3状態を選んだFormDataも、それぞれ実POSTへ渡して保存を確認する。

初回ハーネスの他社/一般利用者テストでは切替前のCSRFを使っていたため、切替後の正規トークン取得に訂正した。
ローカルにはPlaywrightのブラウザキャッシュがなかったため、インストール済みChromeをheadless起動した。CIは固定版PlaywrightのChromiumを使う。
製品修正前の再実行で上記6件の失敗を固定し、製品の期待結果は変えていない。

専用CIは`.github/workflows/q08-patrol-null-edit.yml`。
このジョブは新規16件だけを実行し、旧20件/26件の監査スクリプトはロードしない。
既存の共通CIワークフローの条件・制限時間は変更しない。各headのCI結果はPRへ記録する。

## 再実行

`Q08_PATROL_BROWSER=1`、Playwright 1.62.1のNODE_PATHを設定する。


## 導入と残課題

追加DB変更・移行コマンドはない。既存NULLを変換しない。
旧画面を開いたままでは旧HTMLが未対応を送るため、導入後は編集画面を再読込する必要がある。
今回の契約は、送信された正規状態の明示変更を許すため、旧HTMLのPOSTを世代判定で止める変更は含めない。
作成済み原本・監査履歴を修正せず、新しい監査方式や状態遷移制約も追加しない。

31列監査の残る仕様判断待ち、特に一覧のNULL、未知予定の通知/実施、未知AIの復旧、旧課題の通知状態は未解決として維持する。
本修正はNULL編集の保持だけであり、その意味を未対応・無効・完了のいずれにも決めていない。

本番・保護対象4DB・Render・実外部サービス・他担当worktreeは操作しない。
main直接push、自動マージ、デプロイも行わない。
