# Q05 資料取込の完了日前後関係

基準：main 6df8117。整備請求書・点検資料の確認処理を対象とする。架空の原本PDFと一時SQLiteで検証し、既存データの補充・修復は行っていない。

## 再現した問題

手入力の整備編集は完了日が入庫日より前なら拒否する。一方、資料取込の確認処理は各日付の形式だけを確認し、入庫日・点検日より前の出庫日・完了日を受け付けた。

修正前の追加試験で5件の失敗を再現。整備・点検の確定POSTは302で登録に進み、検証専用POSTは200、車両未指定の整備資料は保留へ進んだ。本事象は仮データによる入力検証不備の再現であり、既存データの逆転を確認したものではない。

## 修正

`validate_vehicle_document_record`で、開始日と完了日が両方あり、両方の形式検証が成功したときだけ前後関係を確認する。

- 整備資料：出庫日が入庫日より前なら出庫日欄のエラー。
- 点検資料：完了日が点検日より前なら完了日欄のエラー。
- 同日、翌日以降、完了日不明は受け付ける。欠損を推定補完しない。
- 請求日・売上日の前後関係は制限しない。
- 形式不正がある欄へ、追加の前後関係エラーを重ねない。

既存の確定・検証専用・車両未指定の経路が共通の検証を使う。既存レコード・DBスキーマの変更はない。エラー時に入力内容を確認用下書きへ保存する既存動作は維持し、整備・点検・部品・保留記録を新規登録しない。

## 検証

追加8件と業務回帰52件、取込フロー12件の計72件が成功（32.256秒）。

- 整備・点検の逆転拒否、正規の日付と精度の確認。
- 同日・うるう日・年越し、完了日空欄の許可。
- 整備・点検の直接確定POSTで業務記録を作らない。
- 車両未指定でも逆転記録を保留へ作らない。
- 検証専用POSTでは下書きも変更しない。
- エラー時も原本を維持する。
- 正常な整備取込で入庫日・完了日と独立した請求日を保持する。
