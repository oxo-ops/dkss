# Q04 PR #273 のmain統合と営業所お知らせ競合

## 原因の切り分け

対象mainは `bb3a1183c8cb9511e9e883351f5df2351f114197`。#281はマージ済みで、追加130件と対応済みのマスタ・関連データ保存保護をそのまま取り込んだ。#273の旧head `02d8a7d` の失敗CIはrun 40673868651。既存マスタ試験の段階を通過し、最後のお知らせ試験6件中4件が失敗していた。

失敗4件は新規・編集のお知らせと営業所の名称変更・削除との競合。お知らせの営業所検証SELECTがロックしないため、その直後にマスタ操作が302で成功した。期待409との相違であり、既存テストの期待値が誤っていたわけではない。現在mainでも、Q08の実User UUIDをcookieへ設定した同じ6件が4失敗することをPostgreSQLで再確認した。通常保存2件は成功した。

#281が対応した納入先・点検・履歴・利用者等の経路を作り直さず、#273の対象であるお知らせの未保護経路を修正する。最新mainにはQ08のセッションUUID検証が加わっており、テストfixtureも実Userの値を設定する必要がある。認可やデータ整合性のアサーションは変更しない。

mainとのテキスト競合は `.github/workflows/q04-postgres-masters.yml` の試験追加位置。mainの全ステップを残し、お知らせの試験を追加して解消した。
