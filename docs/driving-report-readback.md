# 日報OCRの読取候補と検証（2026-10-25）

`INVALID_DRIVING_REPORT_EXTRACTION` は返却項目の検証エラーであり、画面の総称だけでは失敗項目や元の返却値を特定できなかった。画像だけから個別の失敗原因を断定しない。

今回の変更では、API返却値をそのまま保存対象の数値・日付とせず、読取候補の整理と厳格な最終検証を分けた。

- 全角数字、明記された年月日の区切り、正しい桁区切り、明示されたkm接尾辞は表記だけを統一する。運行時刻欄はタイムゾーン付き日時も原文のまま保持できる80文字とする。
- 存在しない日付、年月だけの日付、未記入、非数、負の距離、km以外の距離は、確定値にせず未取得とする。ゼロにせず、出力日・差分・他の単位から補わない。
- 変換や保留が発生した記録は `_ocr_raw_candidate` に返却時の全記録、`_ocr_issues` に該当箇所・返却値・理由を保存する。取込確認の上部と保存後の日報詳細で原文付きの要確認項目を表示する。訂正・復元・保存後も保持する。
- 明細のページが明示され、PDFの範囲内なら確認対象ページへ含める。明細のページが不明・範囲外なら元の明細全体を要確認欄へ残し、集計には採用しない。記録自体のページが特定できない場合や構造・件数が不正な場合は停止する。架空の原本ページを付与しない。
- 未定義の粒度・状態・話者は不明として保持し、AI返却の「確認済み」を人の確認済みとして採用しない。APIスキーマにも粒度・状態・話者の選択肢を指定する。
- 文字数超過も全体を失敗にせず、元の全文を保持して要確認にする。項目名が不明・不完全な指標や解釈できない数値を比較に採用しない。
- 停止する場合は、通常送信・進捗送信の双方で「記録3／原本ページ」等の確認箇所と理由を表示する。ログはフィールドパスを残し、返却された個人情報やAPIキーを診断文へ埋め込まない。

DB列追加・自動API再試行は行わない。以前の失敗時に破棄された返却値をこの変更で復元することはできない。

検証はモック通信、一時DB、実ブラウザで行う。表記ゆれ・欠損・不正数値・ページ参照・長い日時・未定義状態・原文保持・確認画面・保存後詳細・エラーの項目表示を確認する。実APIの今回の返却値は未取得のため、画面に出た個別原因の特定と実APIによる再読取の成功確認は未実施。
