# Q02 削除済み車両の分析ページ参照境界（2026-10-28）

基準: main `6db7eaede9f196606f14e3041b725cf6849cb100`（PR #270反映後）。

## 再現と修正

`GET /vehicle/karte/<id>/analysis` が車両を会社コードだけで取得し、論理削除済み車両についても200でページと集計を返していた。管理者・一般利用者の両方で再現した。
同じ車両の `/analysis/result`、feedback、evaluationは既に削除済みを404で拒否しているため、ページ本体の取得にも `deleted=False` を追加して境界を揃える。

削除済みなら集計やテンプレート処理の前に404となる。通常車両の分析閲覧は一般利用者にも許可する。既存レコード・保存済み分析・履歴は削除しない。

## 試験

既存 `tests/test_q02_analysis_boundaries.py` に3件追加。

- 削除済み車両のページはadmin/userとも404。集計・外部AIを呼ばず、分析・対応・評価・整備・監査のスナップショットが変わらない。
- 現在の車両のページはadmin/userとも200。閲覧で外部AIを呼ばない。
- 旧同期POSTの経路は405であり、外部AIを呼ばないことを確認。

修正前の3件では削除済みのadmin/userの2サブケースが200となり失敗し、正常閲覧とPOST拒否は成功した。修正後のQ02分析境界と分析結果整合性は計22件、10.869秒で成功。
実Flask要求・一時SQLite・合成データで検証。テンプレートと集計は実処理し、外部AIのみ模擬して未呼出しを確認。

## 範囲

公開された分析実行POST経路は存在せず、この修正は外部AI処理中の失効試験ではない。今回見つかったGETページの削除状態チェック漏れだけを修正する。PR #270の取込ワーカー修正、別PR #272のニュース境界、Q04・Q07・運転日報には変更を加えない。
本番画面・Render配備・PostgreSQL専用試験は未実施。Q02全体は引き続き検証中。
