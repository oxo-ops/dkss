# Q02 整備知識の権限と原本の境界

## 対象

分析の根拠になる整備知識について、登録・確認・利用停止の操作者と会社、詳細と原本の取得権限を実Flask要求で検証する。
対象は `/master/maintenance-knowledge`、`/vehicle/maintenance-knowledge/<id>`、`/vehicle/knowledge-documents/<id>/source`。
既存Q02は分析結果・対応・評価を検証しているが、この知識の確認・停止と知識原本の経路は直接検証していなかった。
Q04のマスタ名称・DB制約・並列更新、Q07の費用集計には変更を加えない。

## 追加8件

| 条件 | 確認する結果 |
| --- | --- |
| 管理者が会社・作成者・確認者・停止者・状態を偽装して登録と確認と停止 | 会社と操作者はサーバー側の認証情報。登録はdraft、確認はactive、停止はretired。他社レコードと原本を保持 |
| 両社に同名管理者・知識・原本を用意して他社IDを指定 | 自社詳細とPDFは取得可。他社詳細・PDF・確認・停止は404で、知識・原本・抽出履歴の全列不変 |
| 正規閲覧後に管理者を一般利用者へ降格し、旧Cookieを戻す | 自社詳細と原本は閲覧維持。登録・確認・停止はホームへ戻り、データ不変 |
| 閲覧後にアカウントをロック | 詳細・原本・登録・確認・停止はログインへ戻る |
| 閲覧後にアカウントを削除 | 他社の同名利用者がいても旧Cookieでは取得・更新不可 |
| 閲覧後にパスワードを変更 | 古いCookieで取得・更新不可 |
| 閲覧後に会社を停止 | 古いCookieで取得・更新不可 |
| CSRFを有効化して欠落トークンと別セッションのトークンを送信 | 登録・確認・停止すべて400でデータ不変。同じ経路を現セッションの正規トークンで確認できる |

失効後の拒否は各URLの前に古いCookieを設定して確認する。先行要求でログアウトした結果に依存しない。
CSRFは要求ごとに別アプリコンテキストを使用し、Flask-WTFのgキャッシュを共有しない。
一般利用者の閲覧を新たに管理者限定にはしない。原本はPDF本文の一致、no-store、nosniffを確認する。
