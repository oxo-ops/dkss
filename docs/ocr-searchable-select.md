# OCR取込の候補検索（2026-10-25）

日報・点検記録・整備請求書の対象車両、請求書の対応整備、車検証OCRの車種・営業所で同じ検索付き選択部品を使う。
車両カルテ上部の「車番・車台番号で検索」と同じく、文字入力で候補を出し、クリックで選ぶ。選択済みの車両は入力欄の下へ残す。入力欄から候補を絞って選び、既存のselectが持つID／マスター値だけを送信する。未確定の検索文字列を登録値にしない。検索用の入力欄は共通のJinjaマクロで初期HTMLから描画する。元のselectは既存の送信・復元処理用に非表示で保持し、画面にプルダウンを出さない。

- 車両はナンバー・車台番号の部分一致。空白区切りはAND検索。全角英数字・数字・ハイフン・かな表記の違いを検索時に吸収する。
- 空入力では候補を出さない。入力すると件数と一致候補を表示する。候補は既存の会社限定リストのみを使い、無効車両の表記を保持する。
- 矢印キーで移動、Enterで選択、Escapeで検索を取り消す。IME変換確定のEnterでは選択しない。マウス・タッチでも選択できる。
- 選択解除は空値の候補がある場合だけ可能。必須欄は未選択をエラーとし、任意の車両未選択は既存の登録待ち処理に従う。
- 検索文字を入力したまま未確定の場合は登録を止める。取込対象から外した記録の検索文字は登録を妨げない。選択後は検索文字を空に戻し、選択した車両を下の表示から確認・解除できる。
- 原本の読取値へ戻す操作、車検証の再読取・復元、請求書の動的候補更新、disabled、フォームリセットを同期する。
- 選択欄は元の場所を維持し、スクロールするOCR画面の外にも候補を描画できる。画面端では候補を上へ開く。

`vehicle_karte_selector.js` の共通照合処理をカルテ検索とOCRで共用する。候補行は既存の `vehicle-karte-search-result` スタイルを使用する。OCRの検索欄は `ocr_searchable_select_field.html`、処理は `ocr_searchable_select.js`、追加スタイルは `.css`、読込は `ocr_searchable_select_assets.html` を共用。フォームの送信先・データ構造・照合・会社境界・OCR通信・DBは変更しない。
検索欄は初期状態で無効とし、検索処理の準備完了後に有効にする。検索文字をIDとして送信しない。

検証：600台超の会社限定候補を使い、日報・点検・請求書・車検証の実画面で、全角・車台番号・かな・候補なし・未確定時の送信阻止・選択・復元・必須・動的整備候補・PC・モバイルタッチ・IMEを確認する。点検の実フォーム送信で選んだ車両IDが一時DBへ保存されたことも確認する。実APIは呼ばない。
