# Q12 mobile点検計画のデータ取得後の再配置

## 原因

390px/低速の実計測でCLS約0.058。
API応答後に状態フィルター6個が挿入され、月切替/状態文が64px下へ移動していた。
空表のcolspanセルにも先頭の選択欄のmax-width/floatが適用され、文が縦長になり下部説明が移動していた。

## 変更

mobileで状態フィルターの行を予め確保する（通常2行、380px以下は3行）。
空表セルの選択欄用float/max-widthを解除し、1行分の表領域を確保。
件数を0と偽って表示したり、API/業務集計/権限/ボタン処理を変更したりしない。
PCのCSSは変更しない。共通CSS全体やresponsive_layout.jsも変更しない。

## 確認

実APIの応答を保持したブラウザ試験で、320/360/380/390/600pxの月切替・下部説明のY位置を
応答前後1px未満で維持し、空表が選択欄の幅に縮まらず、状態6個/表示形式切替が使えることを確認する。
1440pxでも表示形式切替とJavaScript例外0を確認する。
これはキャッシュを無効にするinterceptionを使う機能試験であり、通信性能の測定には使用しない。

別のinterceptionなし計測でPC/mobile・通常/低速を各3回測り、中央値/最小/最大を記録する。
架空200台・営業所未設定/予定0件が、約0.058を再現した条件。
多数の予定・大きな件数文字列・エラー状態/文字拡大は別の受入条件として残る。
確定値とCIはPR本文/日本語完了報告を参照。

## 再現

python tools/benchmark_display_fixture.py --port 51320 --work-dir <一時フォルダ>

別端末で node tests/q12_planner_stability_browser.cjs <フォルダ>/fixture.json <結果.json>。
開発用Playwrightとブラウザが必要。Q12_BROWSER_EXECUTABLEで手元のChromeを指定できる。
専用CIは使い捨てSQLite/合成画像で実行し、Cookie/DBを成果物へ保存しない。
長時間計測のfixtureだけセッション有効時間を4時間とし、ログイン状態を必須チェックする。
本番の30分設定は変更しない。並列リクエストの計測JSONLも排他書込みにする。
