# Q12 指摘一覧の添付画像

## 原因と範囲

一覧の75×58px（PC）/120×90px（mobile）の画像にも1600×1000の原寸を取得していた。
指摘一覧の表示だけを160/320/480pxの4:3 WebPへ切り替える。既存の詳細・原本経路は変更しない。
画像枚数/アップロードサイズ/手動圧縮などの利用者負担は追加しない。

profile_images.pyの既存原本版確認・変換・容量制限を再利用する。
storage.pyの会社/ファイル認可後だけthumbパラメータを処理し、認可のキャッシュは作らない。
会社・ファイル・利用者・アカウント世代・原本版・サイズ/用途でキャッシュを分離。
毎要求で元ファイルの存在/版を確認し、HTTP no-storeを維持する。
同時変換はプロセスあたり2件まで待合せ、再確認して変換結果を再利用する。受付枚数の制限ではない。
アニメーション・非画像・未対応サイズ・変換失敗は従来の原本処理へ戻す。

pointouts.htmlのPC/mobile双方でsrcset/sizes、lazy、async decode、幅/高さを指定。
PDF/OCR原本・通知・チェックリスト・詳細画面の画像には適用しない。
Q03の本人/承認判定、Q04/Q08のDB構造、audit.pyには変更を加えない。

## 検証

追加テストは実Flask/一時SQLiteで、原本不変、原本ダウンロード、会社/利用者分離、
認可失効、参照削除、ファイル差替え/欠損、未対応形式/サイズ、詳細の原本経路を確認する。
Fake S3のHEAD再確認/VersionId/拒否、6並列要求の変換上限と再利用も確認する。
既存プロフィール画像の回帰13件を維持する。実S3へは接続しない。

合成画像12枚（1600×1000）、一覧10件、架空200台を同じ条件で比較。
低速は150ms/下り200,000B/s/CPU4倍。PC/mobileで各3回、中央値/最小/最大を分ける。
HTMLのTTFB・app処理・SQL回数、画像実体B、全ネットワーク転送B、load、CLSを別々に集計する。
結果の確定値とCIはPR本文およびQ12の完了報告を参照。

## 再現

python tools/benchmark_attachment_fixture.py --port 51306 --work-dir <一時フォルダ>

Q12_SOURCE_ROOTで各版のcheckoutを指定する。同じツールで版ごとに別フォルダ/ポートを使う。
元画像SHAはattachment_manifest.jsonへ出力される。
Q12のブラウザ計測ツールで/pointouts?page_size=10を両版で同じ件数に固定して比較する。
通常のmobile既定では既存JSがpage_size=5へ再遷移する。今回はこの挙動を変更していない。
遅延画像は最後までスクロールして別途読込みも確認する。
Cookieを含むfixture.jsonや生成DBを成果物へ含めず、自分のサーバーを検証後に停止する。
