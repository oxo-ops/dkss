# 安全運転日報の取込・確認・利用（仕様書v0.21）

2026-10-25。参照原本は過去チャットの `20260923153947.pdf`。
原本・乗務員の実データはリポジトリと配布物に含めない。

## 既存OCRと共通の画面・処理

資料・データ取込の既存フォーム、複数PDF/画像、進捗配信、確認前ドラフト、登録待ち、車両照合、トランザクションを使用する。
通信・構造化出力・原本ハッシュは `maintenance_invoice_ai.extract_vehicle_document`、確認・訂正は `vehicle_document_import_preview.html`、既存CSS・JavaScript・PDF.jsを使用する。
原本照合／明細集中、ページ連動、幅調整、拡大縮小、モバイル切替、検索、修正・原本値への復元を共用する。
点検・日報の項目表と編集欄は `vehicle_document_item_fields.html` に統合した。OCR専用の別レイアウトは追加しない。

## 固定様式に依存しない保持

メーカー・帳票・原本番号・設定版・運行日と出力日時・タイムゾーン・対象粒度（運行／日別／月次／不明）を分離する。
車両・乗務員コードと氏名・所属、開始／終了時刻・場所、積算距離と走行距離、走行／ハンドル／アイドリング／休憩／作業時間、燃料・燃費と単位を保持する。
評価指標、個別事象、乗務・交替・作業区間、独自項目の4コレクションを保持する。
各明細は原文値、数値、単位、分子・分母、定義・検知条件・道路区分、日時・場所・対象、話者、点数・評価・注記・原本ページ・読取状態を分離する。
原本、抽出時の値、人が確認した値、警告、訂正前スナップショットと変更者・日時を追跡できる。

空欄を0にしない。回/hを実回数へ変換しない。グラフの点列や不足値を推定しない。
出力日を運行日にせず、走行距離を積算距離へ転記しない。自動コメントを乗務員本人の発言にしない。
日付・対象不明も保持し、対象不明は既存の登録待ちへ送る。日付不明・粒度不明は距離集計へ加算しない。

## 照合と利用先

- 安全管理 → 運転実績：期間・乗務員・営業所・車両・対応状態の絞込、原本への追跡、確認・指導所見、担当・次回振り返り、担当変更時の既存通知。
- 日報詳細：全明細、原本、既存OCR画面による訂正、CSVとの対応・採用元の確認、取消、変更履歴。
- 車両カルテ：履歴から詳細を開き、走行距離・積算距離・使用実態と既存分析へ接続する。
- AI入力：原本情報、指標の単位・定義・設定版、照合状態、確認所見、出典IDを渡す。取得画面ではAPIを呼ばず、既存のAI実行経路だけを使用する。

CSVとPDFは日報番号または開始・終了時刻を照合し、同じ日という理由だけでは統合しない。
同一運行は一度だけ計上し、距離・積算の不一致は確認まで保留する。人がPDF／CSVの採用元または別運行を保存でき、CSV更新後は保存時の照合条件を再検証する。
取消・置換・月次・粒度不明・日付不明は距離集計へ加算しない。日別集計と同日の運行明細は重ねて足さない。
同一識別の日報同士で距離が矛盾するときも保留する。重複・矛盾した原本は詳細で確認・訂正または取消を行う。
取消した日報があっても、それとは独立に保存済みのCSV運行は削除しない。

数値の推移はメーカー・定義・設定版・単位・道路・対象粒度が同じ場合だけ比較する。
点数の異種平均・順位付けは行わない。分子・分母と分母単位が揃う場合に限り、分子合計÷分母合計を別表示する。
氏名だけで同一乗務員に統合しない。原本のコード・出典・所属を保持する。
事故確率・故障原因・過失・違反・運行可否をこの取込から確定しない。

## 出力と権限

一覧と同じ抽出条件でCSV（UTF-8 BOM、表計算式の実行を抑止）とPDFを出力する。
原文値、単位・定義、実測・時刻・燃料、確認指導内容、担当・次回日、CSV照合と採用元、変更履歴、抽出条件・出力日時・出典IDを含める。
PDFは同梱OFL日本語フォントを埋め込み、端末に日本語フォントがなくても表示できる。追加Python依存は不要。
管理・原本・出力は既存 `require_master_admin` と会社境界を適用する。更新はCSRFと版照合・条件付き更新で競合を検出する。

## データ・適用

既存 `VehicleDrivingReportRecord.details_json`、原本ドラフト、CSV運行参照、通知を利用する。新規テーブル・列の追加、既存レコードの一括変更、API呼出は導入時に行わない。
既存の初期日報取込からの更新と、未適用状態からの導入の両方に対応する配布スクリプトを用意する。
適用前は変更可能性とPython構文を確認し、適用時に対象ファイルをバックアップする。既存編集と競合する場合は停止し、強制適用しない。

## 検証範囲と受入

モック通信、一時DB、純粋な照合計算、PDFの文字抽出と描画、PC・モバイルの実ブラウザ操作で検証する。請求書・点検を含む既存の回帰テストも実行する。
開発環境にOPENAI_API_KEYがないため、実APIによる原本読取精度は未検証。
全世界の帳票への認識精度を保証するものではない。固定様式に依存せず原文と独自項目を保持できる構造とし、実資料による数値・手書き・複数ページ・複数車両の読取品質を受入確認する。
