# 隔離プレビューの原文・条件表示

この変更は合成データ専用の開発接続である。通常環境、保存済み優先度、提案順、提案ID・revision、対応記録、実DB、配備は変更しない。AND条件の採点や月間隔の90%基準は定義・実装しない。

## 有効範囲

既存の `GET /vehicle/karte/<id>/analysis/result?priority_preview=1` の隔離分岐だけを使用する。`TESTING is True`、`MAINTENANCE_PRIORITY_PREVIEW_ENABLED is True`、`RENDER != 'true'`、認証済み admin / itc、既存の会社・車両権限確認が必要である。既定では無効で、リクエストJSONやqueryによる条件・確認フラグの登録経路はない。レスポンスは `Cache-Control: no-store`。

合成データホストが `SyntheticPreviewFixture.timing_conditions` に提案IDをキーとして `SyntheticTimingInput` を登録する。原文・採用ルール・計算結果・`TimingBinding`・提案revision・明示的な意味上の対応確認を含む。登録時に深いコピーを取り、取得時には次を再確認する。

1. 保存済みanalysisとsources全体のハッシュ、および提案ID・revision・対象が元の登録と一致する。
2. 候補と条件の会社・車両・対象・事象・基準日が一致し、ホストが当該提案との意味上の対応を明示的に確認している。
3. 期限計算の出典と事象根拠が、保存済みsourcesと元の提案のsource_ids / knowledge_idsの双方に存在する。引用が存在するだけでは意味上の対応確認としない。
4. 元の採用ルール・条件計算を純粋ブリッジへ再投入し、原文、採用文書checksum、参照バージョン、適用・起算・日数・距離・条件組合せを検証する。JSON化済みの結果を直接受け付けない。

## 別フィールドの契約

元の `analysis` は既存の試行点数投影のまま保持し、`priority_timing_conditions` を別に返す。バージョンは `priority-timing-preview-v1`。共通フラグは shadow / synthetic_only / production_enabled=false。

- `absent`: 条件表示の登録なし。旧レスポンスでフィールド自体がない場合も、条件表示を追加しない。
- `blocked`: 登録や保存版の対応が不正・変更済み。entriesは空で、過去の条件を残さない。生例外は返さない。
- `available`: 検証済み登録を返す。会社・車両・基準日と、提案ID/revisionを付した `timing-condition-view-v1` のentriesを含む。一部の提案だけに条件登録があることも許容する。

entryの `calculation_unavailable` は計算資料の状態であり、優先度の第4区分ではない。条件登録だけが不正な場合は既存の有効な試行点数を消さず、条件部分だけを表示不可にする。保存版全体のハッシュが変わった場合は既存の試算も条件表示も停止する。

## 画面表現

解析詳細の試行カードに、原文、AND（全条件）/ OR（いずれか）/単独、各条件の元の閾値・単位・起算日・参照日・期限日・経過/残り/超過・登録日時点での到達状態を別枠で表示する。原文はテキストとして挿入し、HTMLとして解釈しない。暦月の閾値と日数のカウントダウンは別単位で明記する。

暦条件だけのANDの最終日・ORの最初の日は前段の検証済み事実をそのまま表示する。距離が混在する条件全体の暦上の到達日は推定しない。月90%やAND採点の不足条件は別記する。この接続では条件ブリッジが単独/OR用の入力を返していても、既存点数・並び順には接続しない。`scoring_input_emitted` はブリッジでの入力生成であって、この画面の採点採用済みを意味しない。

データ契約・提案revision・対象・スコープ・基準日・単位・日付・数値が不整合なら条件部分を表示しない。再取得、登録解除、保存版変更、取得失敗時には前回の条件が残らない。

## 検証と残件

専用SQLite合成fixtureと外部通信拒否ガードでAPIを検証し、DOM契約試験で注入文字列・重複表示・不正契約・数値/日付/単位・旧レスポンスを確認する。API取得中のSQL変更、AI処理、キャッシュ更新がないことを確認する。

実ブラウザ受入はこの環境では未実施である。既知のChromium socket権限制約は変わっておらず、再試行やトンネル公開で回避しない。ブラウザと合成アプリが同居する承認済みの隔離環境で、PC/モバイル幅、長い原文、再読込、画面遷移・Back/Forward・中断後復帰を受入する必要がある。過去のPR #361のブラウザ/CI成功を、この未公開差分の成功として計上しない。
