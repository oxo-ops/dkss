# Q02 資料取込中の権限失効（2026-10-28）

基準: main `b9be875312a6ccf952f8eba2946a24c1ed295881`（PR #266反映後）。

## 再現した不具合

既存のワーカーは処理開始時に会社・受付利用者の権限を確認するが、外部処理の結果を反映する時点では再確認していなかった。
分類中にアカウントをロックしても次の抽出処理が開始され、抽出中のロックでは結果が `preview` に保存されることを、修正前の実ワーカー・一時SQLiteで再現した（2件とも期待する拒否結果にならず失敗）。外部AIのみ模擬。

## 修正

`dkss_app/document_import_queue.py` で、会社が有効であり、同社の受付利用者が存在し、ロックされておらず、現在の役割がadmin/itcであることをDBから再取得する。

- 開始時の判定を共通化。
- 分類結果の反映前にも再照合。失効時は種類確認画面の公開・混在資料の子ジョブ作成・次の抽出処理へ進まない。
- 抽出結果の保存前にも再照合。失効時は結果を `preview` として保存しない。
- 失効したジョブは既存の `read_error` と権限確認メッセージにし、previewを空にして処理権のトークンと期限を解除。原本は保持する。

ORMに読み込まれた利用者情報を再利用せず、列のSELECTで現在の状態を取得する。既存の会社コード・利用者名による受付者識別とジョブのlease照合は維持する。

## 回帰検証

`tests/test_q02_import_worker_access.py` に9件追加。

| 処理中の変更 | 分類後 | 抽出後 |
| --- | --- | --- |
| 利用者ロック | 後続抽出・子ジョブ作成を拒否 | preview保存を拒否 |
| 利用者削除＋他社同名管理者 | 同上 | 同上 |
| adminから一般利用者への降格 | 同上 | 同上 |
| 会社停止 | 同上 | 同上 |

さらに、不確実な分類結果でもロック後は `type_review` として公開されないことを確認する。各ケースで原本とハッシュを保持し、整備・点検の業務レコードが増えず、結果に抽出内容が含まれないことを確認する。失効は別アプリコンテキスト・別DBセッションでコミットする。

対象43件（ワーカー権限15件、キュー18件、資料境界10件）成功。JavaScript `tests/document_import_queue_js.cjs` は8件成功。
